## 5. 共同規則（所有角色）
- 先讀 DECISIONS。和決定一致的差異只列「附錄｜已有決定」，不進問題表；標 🔎 的決定一律列「待確認」。
- R1 列過的項目寫 R1 編號（`C-P2-6`、`X-P1` 等），註明已修好／仍存在／修壞了。
- 不確定就列「待確認」，不猜；不為了湊數量而列；偏好不是缺陷。
- 狀態 ✅ ⚠️ ❌ 🔎；優先 P0 擋住任務或資料遺失、P1 影響大、P2 有意義、P3 細節。❌ 一定要有證據。
- subagent 不寫報告檔，結果用文字回傳，由 lead 原文存到 `qa/R2/`。
- 只用假資料庫；不用正式旅程代碼；截圖與工作檔放 repo 外。存進 repo 前清掉行程代碼與個資。
- 每批結束停下來等明彰確認。

## 6. 執行方式
- lead 與三個 qa 都在 claude.ai 的這個 Project 跑：lead 用 Agent 工具派出 subagent，提示內容就是 `.claude/agents/<角色>.md` 的內容（claude.ai 不會自動讀這個資料夾；放在 repo 是為了之後 Mac 上的 Claude Code 也能直接用）。
