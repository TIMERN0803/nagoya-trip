## 第一批：同步與離線（bug，修好就上線，最優先）

根本原因是同一個：`connect()` 要等 `getDocFromServer` 確認代碼後才設 `db`。這段期間的寫入只存在 localStorage，連上後的 onSnapshot 又直接用雲端資料整份取代本機（只有 expenses 有補傳機制）。所以這一批要一起改。

| 編號 | 問題 | 要點 |
|---|---|---|
| C-P0-1 | 連線完成前的勾選、新增、錢包、心情，連上後被雲端蓋掉或不上傳（延遲 3 秒就會發生） | `initializeFirestore` 完成後就設 `db`，SDK 本身會排隊處理離線寫入。代碼權限檢查改到背景做；`permission-denied` 時再退回並提示。`db==null` 期間的寫入存進 outbox（localStorage），連上後先送出 outbox，再掛 onSnapshot |
| C-P0-2 | 程式庫載入失敗（離線開啟）後，恢復網路也不會重連 | 動態 `import()` 失敗後，同一個網址會一直失敗。重試時網址加 `?r=時間戳`，或在 `online` 事件時重新載入頁面（先確認沒有正在輸入的表單）。配合 outbox |
| C-P1-1 | 網路慢或離線時，按「記下這筆」「加進錢包」「送出心情」「儲存訂房資料」沒有回應，再按會重複寫入（實測錢包 2 萬變 4 萬） | 改成樂觀更新：本機先更新、清空或關閉表單、顯示「已記下（恢復網路後同步）」，`set()` 不要 await。新增記帳先在本機產生 doc id，重複按也只會寫同一個 id |
| C-P1-2 | 離線開 App 時，記帳頁顯示 ¥0，現金餘額卻多算 | expenses 快照也要存一份本機快取（和本機新增、`l` 開頭的帳分開存），離線開啟時讀出來顯示 |
| C-P1-6 | 版本更新時，Firebase 程式庫和字型的快取被一起刪掉 | 第三方檔案放在獨立、不隨版本刪除的快取（例如 `ngy-lib`）；或在 activate 時先把它們複製到新快取 |
| X-P2 心情 | 對方刪掉的心情，本機仍顯示（重新整理後也一樣） | moods 的 onSnapshot 不要用 `{...moods}` 合併，要用快照建一份新的 map；尚未同步的本機心情另外放在 outbox |

驗收：
- `claude/scripts/` 的 `t_slowserver.py`、`t_slowlib.py`、`t_offline.py`、`t_coldcash.py`、`t_swlib.py`，以及 `codex/work/run-tools/ft/independent.py` 的 mood_sync，原本 FAIL 的項目要全部變成 PASS。
- 把這些情境整理成正式回歸測試，放進 `ft/`，並在 README 登記。
- 需要 `fs_offline.js`（離線模擬）；tools 原本的假資料庫不會模擬離線。
