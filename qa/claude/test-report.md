## 測試方法與注意事項

- 所有新腳本都放在 `/home/claude/qa/scripts/`，透過 `qa_common.py` 共用設定：
  - 匯入 `ft/fulltest.py`，自己建 browser context
  - 照 `newpage()` 掛上假程式庫，另外擋掉 `**/firestore.googleapis.com/**`、`**/*.googleapis.com/**` 和 `**/firebasejs/**`
- 開發過程中發現：Playwright 是「後註冊的 route 優先」。我第一版把全擋規則寫在後面，導致同步被擋掉，App 走的是「程式庫載入失敗」流程（沒有碰到網路）。修正後，所有結論都重跑過一次。
- **離線行為的模擬**：tools 分支的 `ft/fs.js` 不會模擬 Firestore 離線。所以我另外寫了 `scripts/fs_offline.js`，照 Firestore SDK 文件的行為來模擬：
  - 離線時寫入先在本機生效
  - `setDoc` 的 Promise 要等伺服器確認才 resolve
  - `getDocFromServer` 會 reject `unavailable`

  P1-1 和 P2-1 是用這個模擬做出來的，**建議實機再確認一次**（列在「需要使用者協助的實機測試」第 2 項）。
- **雙機同步**用同一個 context 開兩個 page。因為 `ngy:me` 是共用的，兩頁的身分會一樣。和身分有關的同步（各自的錢包、行李勾選）只驗證到「另一頁看得到資料」，真正分開的身分要實機測。

## 問題清單

### [P0-1] 連線完成之前的勾選、新增、錢包、心情，連上後會被雲端覆蓋或永遠不上傳（訊號差 3 秒就會發生）

- **分類**：同步／資料遺失
- **情境**：日本時間 11/19 20:00，阿彰，程式庫已經在快取，但手機訊號差，`connect()` 裡的 `getDocFromServer` 要 3～12 秒才回應。另一種觸發方式是程式庫本身下載很慢（4～12 秒）。
- **重現步驟**
  1. 開 App（有旅程代碼）。網路慢時 `db` 還是 `null`，清單頁會出現「輸入旅行代碼…開啟共用」表單（見 P2-2）
  2. 這段時間內：勾一個待辦、新增一項「要買的」、錢包補 ¥10,000、寫心情、記一筆帳
  3. 等連線完成（或對方剛好新增一筆，觸發一次快照）
- **預期 vs 實際**

  | 操作 | 連線前畫面 | 連線後畫面 | 雲端 |
  |---|---|---|---|
  | 勾選待辦 | ✔ | **✘ 被取消** | 沒寫入 |
  | 新增「要買的」 | 有 | **消失** | 沒寫入 |
  | 錢包 20000 → 30000 | 30000 | **20000** | 20000 |
  | 心情 | 有 | 有（只在本機） | **沒寫入，對方看不到** |
  | 記帳 | 有 | 有 | 有（有補傳機制） |

  延遲 3、4、10、12 秒結果都一樣。

- **原因**
  - `db` 要等 `getDocFromServer` 成功後才指定（index.html 約 2498–2500 行）。在那之前，`saveItem`、`saveWallet`、`saveMood`、勾選都只寫 localStorage。
  - 連上後，`items`、`checks`、`wallet` 的 onSnapshot 直接用雲端資料整個取代本機（2504–2514 行）。
  - 只有 `expenses` 有「把 `l` 開頭的本機帳搬上去」的邏輯。
- **證據**
  - `scripts/t_slowserver.py`：6 項 FAIL
  - `scripts/t_slowlib.py`：8 項 FAIL（`out_slowlib.json`、`out_slowserver.json`）
  - 截圖：`shots/slowlib_4000_list.png`（連線中卻顯示「輸入旅行代碼」）、`shots/slowlib_4000_after.png`（連上後新增的項目不見了）
- **建議修法**
  - 不要等 `getDocFromServer` 才指定 `db`。Firestore SDK 本身就有離線佇列。`initializeFirestore` 完成後就設 `db=fdb`，把代碼權限檢查放到背景做，失敗再處理。
  - 或者把 `db==null` 期間的寫入存成 outbox（localStorage），連上時先送出 outbox，再掛 onSnapshot。

  ```js
  // connect() 內
  db=fdb; live=true; syncMsg="";              // 先讓之後的寫入都走 SDK（SDK 會自己排隊）
  F.getDocFromServer(...).catch(err=>{ if(err?.code==="permission-denied"){ /* 退回、提示代碼錯 */ } });
  await flushOutbox();                         // 送出 db==null 時存下的本機變更
  ```
- **能否用自動化測試涵蓋**：是（`t_slowserver.py`、`t_slowlib.py`）

### [P0-2] 程式庫載入失敗（離線開啟）之後，恢復網路不會重新連線；離線期間的清單、勾選、錢包、心情永遠不會上傳，重開 App 後還會被蓋掉

- **分類**：離線／同步／資料遺失
- **情境**：日本時間 11/19 20:00。App 開啟時沒有網路，或 Firebase 程式庫不在快取裡（見 P1-6：每次版本更新後的第一次開啟就是這樣）。之後網路恢復。
- **重現步驟**
  1. 程式庫載入失敗的狀態下開 App，畫面顯示「目前離線，先記在這支手機上」
  2. 新增要買的、勾待辦、記帳 ¥1,200、錢包補 ¥5,000（20000 → 25000）、寫心情
  3. 觸發 `online` 事件
  4. 關掉 App 再打開（有網路）
- **預期 vs 實際**
  - 步驟 3 之後：`live=false`、`syncMsg="offline"`，**沒有重新連線**。原因是動態 `import()` 失敗的結果會被瀏覽器的 module map 記住，同一個網址再 import 一定失敗。
  - 步驟 4 之後：

    | 資料 | 雲端 | 本機 |
    |---|---|---|
    | 記帳 | ✔ 上傳 | ✔ |
    | 要買的 | **✘** | **消失** |
    | 勾選 | **✘** | **消失** |
    | 錢包 | **20000** | **20000**（補的錢不見） |
    | 心情 | **✘** | 只在本機 |
- **證據**：`scripts/t_offline.py` 的「離線補傳」11 項中 10 項 FAIL（`out_offline.json`）、截圖 `shots/offline_reopen_list.png`
- **建議修法**
  1. 重新連線時用不同的網址 import，例如 `firebase-app.js?r=${Date.now()}`。或在 `online` 時直接 `location.reload()`，但要先確認沒有正在輸入的表單。
  2. 和 P0-1 一樣，`db==null` 期間的所有寫入（items／checks／wallet／moods／settings）都放進 outbox，連上後送出，再掛 onSnapshot。
- **能否用自動化測試涵蓋**：是（`t_offline.py`）

### [P1-1] 網路慢或離線時，按「記下這筆」「加進錢包」「送出心情」「儲存訂房資料」，畫面停住沒有回饋，再按一次就會重複寫入

- **分類**：離線／資料重複／金額
- **情境**：程式庫已快取、手機離線（Firestore 真實行為：寫入在本機生效，Promise 等伺服器確認才 resolve）。另外用 tools 的 `window.__writeDelay=3000` 模擬「網路很慢但有連線」，也能重現。
- **重現步驟（記帳）**
  1. 離線，記帳頁輸入 3000、備註「拉麵」，按「記下這筆」
  2. 金額欄還是 3000，按鈕變灰，沒有出現「已記下」，但下方列表已經多一筆（截圖 `offline_acct_after_save.png`）
  3. 切到其他分頁再回記帳頁：表單重畫，**金額 3000 還在，按鈕又能按了**
  4. 再按一次 → 恢復連線後雲端有 **2 筆「拉麵」**
- **重現步驟（錢包）**：離線打開錢包 → 補錢 10000 → 按「加進錢包」。表單沒關，上方餘額已經變了。再按一次 → 雲端 `cashIn` 從 **20000 變成 40000**（`offline_wallet_after_add.png`）
- **心情和訂房資料**：按送出後表單也不會關（`offline_mood_after_submit.png`）
- **慢網路（有連線）**：按記下 → 切到清單 → 回記帳 → 金額還在 → 再按一次，雲端 2 筆 ¥888（`acct_slow_tabswitch.png`，`t_money.py`）
- **原因**
  - 記帳 submit 是 `await ref.set(rec)` 完成之後才清空表單、顯示「已記下」（約 2427 行）
  - 錢包 submit 是 `await saveWallet()` 之後才關表單
  - 心情是 `await saveMood()` 之後才重畫
- **建議修法**：寫入改成「樂觀更新」。本機先更新、清空表單、顯示「已記下（等網路恢復會自動同步）」，`set()` 不要 await，或只在背景接 `.catch()`。新增記帳時先在本機產生 doc id，重複按也只會寫同一個 id。
- **能否用自動化測試涵蓋**：是（`t_offline.py` 的「離線（已快取）」，需要 `scripts/fs_offline.js`；慢網路版本在 `t_money.py`）

### [P1-2] 程式庫載入失敗時開 App，記帳頁顯示 ¥0、清單空白，現金餘額多算（實際 ¥10,000 卻顯示 ¥30,000）

- **分類**：離線／金額
- **情境**：阿彰的錢包換了 ¥30,000，現金已付 5 筆共 ¥20,000（已同步）。之後在沒網路或程式庫不在快取的狀態下開 App。
- **預期 vs 實際**
  - 預期：首頁膠囊和記帳頁顯示 ¥10,000，列表看得到之前的帳
  - 實際：「我的現金 **¥30,000**」、旅程總花費 **¥0**、「還沒有記帳」。阿彰會以為口袋裡還有 3 萬
- **原因**：連線時 expenses 的 onSnapshot 不會寫入 `store.set("exp")`；只有 `db==null` 時才存（2513 行對照 2425 行）。wallet 有快取，帳沒有快取，所以兩者對不起來。
- **證據**：`scripts/t_coldcash.py`、截圖 `shots/offline_acct_coldstart_cash.png`
- **建議修法**：expenses 快照也要 `store.set("exp-cache", …)`，離線開啟時讀出來顯示（唯讀或標示「離線資料」），要和本機新增的 `l` 開頭帳分開存。
- **能否用自動化測試涵蓋**：是

### [P1-4] 修改一筆舊帳（或按「取消修改」）之後，下一筆新帳的付款人、分攤、日期、付款方式會沿用那筆舊帳

- **情境**：日本時間 11/21 12:00，阿彰修改星星 11/18「自己的、付現」那筆帳

### [P1-5] 兩人同時修改同一筆帳時，後存的人會整筆覆蓋先存的人的修改；刪除中的帳會被對方「更新」寫回來

- **嚴重度說明**：照定義「覆寫對方資料」屬於 P0。但要兩人同時打開同一筆帳才會發生，機率低，所以先列 P1，請使用者決定。

### [P1-6] 版本更新時，Firebase 程式庫和字型的快取會跟舊快取一起被刪掉；更新後第一次開 App 之後如果沒網路，就會走進 P0-2

- **分類**：離線
- **情境**：sw.js v44 → v45（用 `/home/claude/qa/site_v44`、`site_v45` 複本在 8767 埠測）
- **觀察**

  |---|---|

  | 再重開一次 | 才補回來 |

  原因：activate 把舊版快取整個刪掉，而第三方檔案不在 CORE 清單裡。如果更新後只在旅館 Wi-Fi 開過一次，隔天在街上沒訊號打開，就沒有 Firebase 程式庫可用。

  - 或在 activate 時，把舊快取中 gstatic／fonts 的項目複製到新快取再刪掉舊的
- **能否用自動化測試涵蓋**：是（`t_swlib.py`）

### [P2-1] 離線（程式庫已快取）時仍顯示綠色「同步中」

- **分類**：離線／文案
- **說明**：Firestore 離線時 `getDocFromServer` 會 reject `unavailable`，但程式只把 `permission-denied` 當錯誤，其他錯誤都繼續、設成 `live=true`。所以離線冷啟動和離線中都顯示綠色「同步中」，委託書提到的「目前離線，先記在這支手機上」不會出現。這也違反「綠色只用在同步成功」的設計規範。
- **證據**：`t_offline.py`「手機離線時狀態不應仍顯示綠色同步中」「離線冷啟動」2 項 FAIL、截圖 `shots/offline_coldstart_list.png`
- **建議**：監聽 `online`／`offline` 事件和 `navigator.onLine`。離線時顯示「離線中，會自動同步」（中性色），連線後恢復綠色。
- **能否用自動化測試涵蓋**：是

### [P2-2] 連線中（程式庫或伺服器回應慢）時，畫面顯示「輸入旅行代碼」表單，代碼其實已經存好了

- **說明**：`syncMsg` 初始是空字串，只有使用者按「開啟共用」才會設成 `"connecting"`。App 自動連線期間會顯示代碼輸入框，第一次用的星星會以為要重新輸入。實測慢網路下重新輸入後，會一直顯示「連線中…」。
- **證據**：`shots/sync_lib_hang.png`、`shots/slowlib_4000_list.png`、`shots/sync_lib_hang_reenter.png`
- **建議**：`connect()` 一開始就設 `syncMsg="connecting"`，並設 10 秒逾時，逾時後改成離線狀態。
- **能否用自動化測試涵蓋**：是

### [P2-4] 金額輸入：小數點被吞掉（12.5 → 125）、全形數字被清空、錢包「1.5萬」變成 ¥15

- **分類**：功能／金額
- **說明**：`#f-amt` 用 `replace(/[^\d]/g,"")` 過濾輸入，`"12.5"` 會變成 `125`、`"1e5"` 會變成 `15`、`"１２３"`（全形）會變成空字串。錢包輸入框同樣處理，`"1.5萬"` 會變成 15。日圓雖然沒有小數，但打錯會被無聲地放大 10 倍。
- **證據**：`t_money.py`「記帳輸入」「錢包」

### [P2-5] 匯率可以手動輸入不合理的值（0.0001、9.9）；離線時按「改回自動」，重開後又變回手動

- **建議**：手動範圍和自動一樣（0.1～0.5），超出範圍要提示。按「改回自動」時同時把 `settings/rate` 寫成 `{auto:true}`。

## 使用體驗建議

依「旅途中的影響」排序。

1. **迷路時拿到「給司機看」太慢**（第一優先）
   - 現況：旅途中打開是當天行程頁，沒有求助按鈕（P2-9）。求助面板每次預設停在「日常日文」（委託書說這是刻意設計），飯店卡在「緊急求助」分頁的第一張。最短路徑要 4 下（`shots/ux_zhang_01_open_morning.png` → `ux_zhang_09_sos_default.png` → `ux_zhang_10_sos_emg.png` → `ux_zhang_11_hotel_show.png`）。
   - 問題：單手、緊張時，每多一步就多一個出錯機會。
   - 建議：每頁都有求助入口。在「日常日文」分頁頂端也放一條「🏨 給司機看飯店地址」的大按鈕，任何分頁都能一鍵打開。
   - 改動大小：小

2. **離線或慢網路時，寫入要立刻給回饋**
   - 現況：見 P1-1。按了沒反應，按鈕變灰。
   - 建議：統一使用「已記下，網路恢復後同步」的 toast，同步狀態膠囊顯示待同步筆數。
   - 改動大小：中

3. **記帳要先捲動才看得到表單**
   - 現況：一進記帳頁，上半部是總花費卡，金額欄在 y≈385，按鈕在 y≈474–527。表單選項很多，結帳時要記一筆需要「輸入金額 → 選類別 → 確認付款人 → 確認現金 → 選免稅 → 備註 → 記下」，至少 3～4 下（`shots/ux_zhang_05_acct_top.png`、`ux_zhang_06_acct_form_filled.png`）。
   - 建議：表單放到總花費上面，或預設收合總花費卡。付款人、付現保持上一次的設定（修好 P1-4 之後）。輸入金額後，按鈕可以直接顯示「記下 ¥8,800」。
   - 改動大小：小～中

4. **鍵盤彈出時看不到「記下這筆」**
   - 現況：390×470 可視區時，focus 在金額欄，送出按鈕在畫面外（`shots/ux_zhang_08_acct_keyboard.png`）。
   - 建議：金額欄加上 `enterkeyhint="done"`，按 Enter 直接送出。或在金額欄右側加一顆小的「記下」按鈕。
   - 改動大小：小

5. **代碼和身分的設定流程**
   - 現況：拿連結 `#k=` 打開會自動帶入代碼、跳出教學，教學結束後進出發前設定並詢問身分，流程順（`shots/ux_star_01…04`）。但如果按了「略過」，就不會被問身分（P2-11）；手動輸入代碼的人沒有錯誤保護。
   - 建議：略過教學時仍跳出「你是哪一位？」，代碼不存在時要提示。
   - 改動大小：小

6. **過期待辦與最後一天的提醒**
