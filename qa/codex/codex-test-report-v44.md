## 問題清單

### [P1] 金額欄位會把無效輸入改成另一個有效金額

- 分類：功能／金額正確性／錯誤預防。
- 情境：日本時間 11/18 20:00，390×844，假資料庫，任一付款人。
- 重現步驟：1. 進入記帳。2. 貼上 `1.5`。3. 輸入備註後按「記下這筆」。4. 查看假資料庫的 expenses。
- 預期：僅接受明確的正整數日圓；小數、負數、科學記號及超出上限的值應拒絕並提示，避免改變使用者原意。
- 實際：`1.5 → 15`，保存的 `amt` 確實是 15；`-100 → 100`、`1e3 → 13`、`999999999 → 99999999`。`99,999,999` 正常解析為 99999999；0、空字串與純空白則有拒絕。
- 證據：`evidence/independent/results.json` 的 `amount_input_*`、`decimal_saved_without_reinterpretation`；`evidence/independent/amount-decimal-saved.png`。原始碼 `index.html:2381` 在輸入時刪除非數字並截斷 8 碼，`2410` 附近再 parseInt。
- 建議修法：保留原始輸入，在送出前做完整格式驗證；若接受千分位，先驗證合法分組再去除逗號。拒絕小數、負號、字母和超額輸入，顯示「請輸入 1–99,999,999 的整數日圓」。錢包表單也使用去除非數字的模式，應一併檢查；本次實際錯誤寫入證據來自記帳表單。
- 可自動化：是，`independent.py::money`。回歸條件應檢查「不寫入＋原值保留＋顯示提示」，不能只看畫面顯示有變化。

### [P2] 另一端刪除心情後，本機每日心情仍顯示舊內容

- 分類：同步／資料一致性。
- 情境：日本時間 11/18 21:00，同一 context 的兩個 page，共用假資料庫；兩頁使用相同身分，以排除 mock 身分共用的干擾。
- 重現步驟：1. A 寫入一則心情。2. B 透過相同假 Firestore API 刪除該文件。3. 等待 storage 通知。4. 查看 A 每日心情。5. 重新整理 A 再查看。
- 預期：文件刪除後，所有訂閱端移除該則心情及相關摘要。
- 實際：mockdb 的 mood 文件數已是 0，A 每日心情仍顯示舊筆記；重新整理後仍能重現。首頁摘要不顯示完整筆記，所以「首頁找不到筆記字串」不能當作刪除成功證據。
- 證據：`evidence/journey/13-deleted-mood-still-visible.png`、`evidence/journey/deletion-reload.json`：`daily_stale_after_reload: true`、`remote_mood_count: 0`；`evidence/independent/results.json` 的 `remote_mood_delete_clears_daily`。
- 原因線索：`index.html:2520` 附近 moods 的 onSnapshot 使用 `{...moods}` 再加入現有文件，沒有清除快照中已消失的 key；舊資料也會再存入本機快取。
- 建議修法：完整 collection snapshot 應建立新的 mood map，再取代舊 map；若需保留未同步資料，應另以 pending 集合與寫入狀態管理，不能把整個舊 map 無條件合併。同步更新後也要驗每日頁、首頁與回顧。
- 可自動化：是，`independent.py::mood_sync`、`journey.py`、`final_probe.py`。此處直接操作 mock API 是為了精準控制遠端刪除；真實雙機仍需驗證。

### [P2] 多個彈窗缺少一致的焦點進入及 Esc 關閉

- 分類：無障礙／鍵盤流程。
- 情境：出發前首頁，外接鍵盤，390×844。
- 重現步驟：1. 開啟求助、錢包、行事曆或出發前設定面板。2. 查看 activeElement。3. 按 Esc。
- 預期：開啟時焦點移入面板，Esc 可關閉，關閉後回到觸發按鈕；螢幕閱讀器能辨識模態範圍。
- 實際：求助、行事曆與出發前設定開啟時焦點未移入；錢包未設定時會移入金額欄位。四種面板按 Esc 均未關閉。均有 role=dialog，但未設 aria-modal。回顧故事有 Esc 行為，體驗不一致。
- 證據：`evidence/independent/results.json` 的 `open*_focus_enters_dialog`、`open*_escape_closes`。共 7 個失敗檢查，歸為一個問題，未算成 7 個問題。
- 建議修法：共用 dialog lifecycle：保存 opener、移入焦點、管理 Tab 循環與背景 inert、監聽 Esc、關閉還原焦點；正確設 aria-modal。完整焦點循環與 VoiceOver 仍需後續驗收，本輪沒有宣稱全部已驗證。
- 可自動化：是，`independent.py::modal_keyboard`；另補 Tab／Shift+Tab 與關閉後 focus 回歸測試。

### [P2] 記帳選項及部分操作按鈕低於委託書的 44×44 px 目標

- 分類：無障礙／單手操作。
- 情境：390×844，記帳與清單頁。
- 重現步驟：1. 開啟記帳。2. 量測類別、付款人、分攤與付款方式按鈕的 DOM bounding box。3. 查看清單編輯操作。
- 預期：依本案規格，操作目標至少 44×44 CSS px。
- 實際：記帳的類別按鈕約 72×32、分攤按鈕約 80×32、付款方式約 72×32；清單部分編輯按鈕 40×40、排序約 66×30。勾選框本體 26×26，但包覆 label 可能擴大點擊區，本輪沒有只憑本體尺寸就判定全部勾選區不合格。
- 證據：`evidence/independent/layout-complete.json`、`evidence/journey/05-checkout.png`。這是本案 44 px 規格未達，不等同宣稱全部不符合 WCAG 2.2 AA 的 24 px 最低目標條款。
- 建議修法：按鈕 min-height:44px，圖示按鈕 min-width:44px；控制相鄰目標間距，優先處理結帳時常用的類別、付款人、現金／刷卡。
- 可自動化：是，`independent.py::layout` 會輸出尺寸；應把尺寸門檻納入正式回歸斷言。

### 假資料庫與隔離方法

一般測試的每個 browser context 均攔截 Firebase SDK，以 `ft/app.js`／`ft/fs.js` 回應；其餘外部網域預設 abort，並另封鎖 Firestore。這也補上「自建 context 未繼承 newpage 路由」的委託書地雷。Service Worker 預設停用，避免 worker 發出的網路請求繞過 Playwright 路由。

SW 測試改用 `localhost:8767`：僅測試 fixture 將 Firebase import 指向同源假 SDK，回應 CSP `connect-src 'self'` 等限制；App 邏輯與 sw.js 沿用原版。此處沒有開啟正式 App，亦沒有使用真實 Firebase SDK。隔離 fixture 的 CSP／來源變更會影響字型與外部服務，故結果只證明本地快取機制，不能替代正式站部署驗證。

兩頁同步使用同一 browser context，依 mock 的 storage 事件同步；身分 localStorage 共用，所以不能當成兩支獨立手機。48 次心情編輯明確在程序中切換 `me`，只驗儲存與聚合；沒有將它冒充真實帳號權限測試。

## 使用體驗建議

依旅途中影響排序：

1. **現場結帳**：頁面能清楚選付款人、分攤與現金／刷卡，但金額改寫會直接影響帳目。先修 P1，再把常用選項增高到 44 px；改動小～中。證據：05-checkout、amount-decimal-saved。
2. **記帳後確認現金**：未設定錢包時，仍能記帳，但只能看到「還沒設定」。建議首次現金記帳後加一個不阻擋的設定錢包入口，讓人知道現金餘額尚未可用；改動小。證據：06-wallet。
3. **找求助與飯店地址**：首頁求助入口清楚，放大地址為白底大字，適合給司機看。從首頁需「求助→緊急求助→給司機看」3 次點擊；可考慮在求助頁保留直接到飯店地址的快捷動作，依單手場景實測再決定；改動小。證據：07-driver-address。
4. **大量資料**：1,000 筆時仍整份重畫；CPU4× 已有約 1.2 秒。建議按日期摺疊／分批顯示，保留總計計算完整資料；先用真實低階手機確認再選是否虛擬化；改動中。
5. **字體放大**：CSS zoom 模擬讓頂部標題與工具列擠壓。應優先驗真實 Safari 200% 與系統大字，再允許工具列換行或收斂標籤；改動中。此處是待驗線索，不算已確認瀏覽器缺陷。

## 需要使用者協助的實機測試

這些是待執行步驟，不是本次已通過的測試。真實同步若要寫入正式 Firestore，需先由使用者決定環境與額度；**本次沒有執行，也不要自行編一個代碼就以為是測試庫**。

1. **兩支手機身分與同步**：在明確授權且有備份的測試環境，A／B 各選不同身分。交錯新增、改同筆金額、改付款人、刪心情、勾各自行李／錢包、排序碰上新增。每步比對兩邊與重開後內容；記錄延遲與是否有遺失。
2. **斷線與重連**：先線上開好 App，再飛航模式記帳／勾選／寫心情；確認離線文字。另一台同時改相同項目，恢復網路後比對結果。辨識「尚未同步」與「已完成」，不要只看樂觀顯示。
3. **iOS 安裝與更新**：Safari 分享→加入主畫面；關閉瀏覽器、主畫面重開；驗瀏海／Home Indicator。更新版本後確認新 SW 接管、舊快取清除、離線仍可開。未曾線上快取的裝置不應期待第一次離線就能載入。
4. **鍵盤與大字**：320／375 尺寸手機開錢包及保險輸入，叫出鍵盤並旋轉；儲存與關閉仍需可見。Safari 200% 頁面縮放及系統大字都測，與 CSS zoom 模擬分開。
5. **日文語音**：有／無已下載日文聲音、getVoices 初始空陣列、靜音模式、離線各驗一次；連點及關閉後不得殘留播放。確認「〇〇」與飯店數字讀音。
6. **回顧分享**：空資料與完整 16 則心情各存一次；確認 iOS 分享面板、取消後可重試、圖片清晰且尺寸正確。原生分享不是 download 事件，需看面板與最後存檔結果。
7. **提醒與背景**：App 前景驗行程前 30 分鐘；訂閱行事曆後關閉 App 驗提醒。夜間留背景，跨日返回，檢查今天、下一站與最後一天不出現「回家」。
8. **戶外／無障礙**：強光下讀焦糖棕小字、珊瑚警示、插圖文字；VoiceOver／TalkBack 檢查分頁、浮動按鈕、dialog、勾選狀態及朗讀順序。這些不能由桌面截圖給合格結論。
