## 0. 安全規則（最重要，請先讀）

這個 App 已經上線，兩位使用者（阿彰、星星）在 **2026/11/17–11/24** 旅途中會實際使用。雲端資料是真實的。

| 規則 | 說明 |
|---|---|
| **不要連真實的 Firestore** | 預設一律用 tools 分支的假資料庫（見第 2 節）。Firebase 專案 `nagoya-trip-4cdde` 是正式環境，**任何旅程代碼**都會寫進同一個正式資料庫，包括你自己編的代碼。 |
| **絕對不要輸入正式旅程代碼**（代碼不寫在公開 repo；需要時問使用者，且只用來「確認不要用」） | 這是兩位使用者真正的旅程。對它的任何寫入、刪除、排序、勾選都會同步到他們的手機。 |
| **不要對正式網站或 Firestore 做壓力測試** | Firebase 是免費方案，每日讀寫有額度上限。灌爆額度會讓他們在旅途中無法同步。壓力測試只在本機的假資料庫上做。 |
| **不要 push、不要開 PR、不要改 `main` 或 `tools` 分支** | 你的產出只有測試報告（和你自己寫的測試腳本，放在本機或報告附件）。修正與上線由另一個流程負責，需要使用者確認後才會發布。 |
| **不要提交私人資料** | repo 是公開的。訂房資料只存在雲端與 `.sos-private.json`（已 gitignore），報告裡也不要貼訂單編號、姓名等。 |
| 正式網站只能「看」 | `https://timern0803.github.io/nagoya-trip/` 可以打開觀察（不輸入旅程代碼、不按任何會寫資料的按鈕），主要用來確認離線快取與實機行為。 |

如果某個測試**一定**要用真實 Firestore 才能驗證（例如真實雙機同步的延遲），請不要執行，在報告裡列為「需要使用者協助的實機測試」，寫清楚步驟即可。

## 1. App 概要

- **網站**：https://timern0803.github.io/nagoya-trip/（GitHub Pages，`main` 分支即線上版）
- **Repo**：`TIMERN0803/nagoya-trip`（public）
- **架構**：單一 `index.html`（CSS / JS / SVG 全部內嵌，約 29 萬字元），`sw.js` 是 Service Worker（版本號每次上線 +1，以 repo 上的為準），資料存 Firebase Firestore（以旅程代碼分隔，無登入）
- **使用情境**：兩人各用一支手機，加到主畫面當 App 用；大部分時間在日本，網路可能不穩
- **時區**：行程判斷一律用日本時間（Asia/Tokyo）；首頁插圖時段看手機本地時間
- **設計規範**（請用來檢查視覺一致性）：
  - 主色焦糖棕 `--accent #946645`
  - 綠色**只**用於「今天／現在／下一站」與成功、同步狀態
  - 警示用珊瑚色（例如現金不足、過期待辦）
  - 外框卡片：淺棕外框 `#8C6D55` 加同色實心陰影；內層選項不加框，用底色區分
  - 手繪粗線條、遊戲感；角色只有原創的白貓「豆花」、黑貓「芝麻」

## 2. 本機測試環境

既有的測試工具在 repo 的 **`tools` 分支**，腳本裡的路徑寫死，請照這個結構放：

```bash
git clone -b tools https://github.com/TIMERN0803/nagoya-trip.git /home/claude/build
git clone https://github.com/TIMERN0803/nagoya-trip.git /home/claude/nagoya-trip
cd /home/claude/nagoya-trip && python3 -m http.server 8766 &   # 本機伺服器
cd /home/claude/build && node mkdays.js                         # 產生 /tmp/days.json（測試前必做）
```

（如果你的環境不能用 `/home/claude`，可以用軟連結，或在自己的副本裡改路徑；**不要**把改過的路徑推回 tools 分支。）

- **假資料庫**：`ft/app.js`、`ft/fs.js` 取代 Firebase 程式庫。`fulltest.newpage()` 會用 Playwright 攔截 `firebasejs/**`，把它們換成假的，並擋掉天氣、匯率、字型的外部請求。**你寫的新腳本請一律沿用 `ft/fulltest.py` 的 `newpage()`**，就不會碰到真實 Firestore。
- ⚠️ **地雷**：`newpage(..., ctx=自己建的context)` 時，攔截**只在 newpage 自己建 context 時才會掛上**，傳入的 ctx 不會有假資料庫，頁面會去載入真正的 Firebase。自己建 context 時（例如要設 `device_scale_factor` 截高解析度圖），請先在 ctx 上掛同樣的 `route`（照抄 `newpage()` 裡那幾行），並額外擋掉 `**/firestore.googleapis.com/**`。
- **預先塞資料**：在 init script 寫 `localStorage.setItem("mockdb", JSON.stringify({...}))`，路徑格式 `trips/<代碼>/items/<id>`、`trips/<代碼>/expenses/<id>`、`trips/<代碼>/settings/meta` 等，範例見 `ft/nexttest.py`。
- **模擬時間**：`newpage(b, ft.jst(月,日,時,分))`（日本時間）或 `ft.twt(...)`（台灣時間），內部用 `page.clock.install`；要讓時間往前走用 `page.clock.fast_forward("hh:mm:ss")`。
- **模擬時區**：`newpage(..., tz="Asia/Taipei")`。
- **身分 / 代碼**：`newpage(..., me="zhang" 或 "star", code="neko-test")`。測試代碼請用 `neko-test` 這類，**只在假資料庫裡用**。
- **插圖時段**：網址加 `?scene=morning|noon|afternoon|night` 可強制顯示。
- **注意**：旅途中 App 打開預設在當天行程頁，要點 `[data-home]` 回首頁；首頁會自動捲動，點插圖前先 `scrollTo(0,0)`；貓有呼吸動畫，Playwright 點擊要 `force=True`。
- **伺服器**：背景啟動的 `http.server` 可能被環境停掉，出現 `ERR_CONNECTION_REFUSED` 就重開。

## 3. 要測的內容

### 3.1 情境測試（時間 × 地點 × 狀態）

請至少涵蓋下列時間點，每個都看首頁、當天行程頁、浮動按鈕、提醒是否合理：

| 情境 | 時間（日本時間，除非註明） |
|---|---|
| 剛裝好、出發前很久 | 台灣時間 10/25 18:00 |
| 出發前一晚、前一刻 | 台灣時間 11/16 23:59 → 11/17 00:01 |
| 出發當天在台灣機場 | 台灣時間 11/17 早上 |
| 抵達、行程進行中 | 11/17 中午、傍晚 |
| 行程之間的空檔、整天在同一地點（吉卜力） | 11/18 13:00 |
| 晚餐進行中 → 行程結束「回家」 | 11/17 21:00 → 22:30 |
| 只剩彈性行程的夜晚 | 11/21 21:30 → 22:10 |
| 跨午夜 | 11/18 23:59 → 11/19 00:01 |
| 最後一天機場、起飛後 | 11/24 07:30、15:00 |
| 旅程結束後（回顧頁） | 11/25、12 月 |
| **手機時區沒切換**（人在日本但手機還是台灣時間） | 用 tz=Asia/Taipei 模擬旅途中各時間 |
| 長時間開著不關（App 留在背景整晚） | 用 `clock.fast_forward` 跨越時段、跨日 |

### 3.2 功能測試（每個功能的邊界）

- **輸入邊界**：空字串、只有空白、超長文字（500 字以上）、emoji、日文、HTML／`<script>` 字元（檢查 XSS 與跳脫）、極大金額（¥99,999,999）、0、負數、小數
- **記帳**：多幣別換算、分攤給一人／兩人、改付款人後錢包餘額是否正確、現金餘額剛好為 0 與變負數、免稅門檻 ¥4,999 / ¥5,000、匯率抓取失敗時的備援與手動覆寫
- **待辦期限**：沒期限、只有日期、日期＋時間、已過期、同一分鐘多筆、期限在旅程結束後
- **刪除與復原**：連續刪除多筆再復原、5 秒倒數中切分頁、復原時對方手機也刪了同一筆
- **排序**：拖到最上／最下、拖曳中切分頁、排序時另一支手機新增項目
- **心情**：同一天兩人都寫、編輯別人的、刪除後首頁摘要
- **求助**：全螢幕顯示的關閉方式、撥號連結格式（`tel:`）、旅平險欄位編輯同步、分頁與情境篩選切換、捲動時標題固定
- **語音**：沙箱沒有聲音，請比照 `ft/voicetest.py` 用 init script 換掉 `window.speechSynthesis` 記錄 `speak()` 收到的文字與語言。檢查連點播放、播放中關閉、播放中切到另一句、沒有日文語音、`getVoices()` 一開始回傳空陣列（iOS 常見）等情況。實際音質與 iPhone 靜音模式能否發聲列入「需要使用者協助的實機測試」
- **彈出面板**：各種螢幕尺寸與橫向、鍵盤彈出時（輸入旅平險、錢包金額）按鈕是否仍點得到
- **回顧**：沒有任何資料時、資料很多時、「存成圖片」在 iOS Safari 是否可用（無法實測就列入實機清單）
- **浮動按鈕「回家」**：導航網址（目的地 Place ID、大眾運輸、無出發地）、分頁切換時隱藏、隔天恢復

### 3.3 同步與離線（只用假資料庫）

- 模擬阿彰和星星**同時**操作：新增、勾選、刪除、排序、改同一筆記帳
  - 假資料庫（`ft/fs.js`）把資料存在 `localStorage["mockdb"]`，靠 `storage` 事件通知其他分頁。所以「兩支手機」要開成**同一個 browser context 裡的兩個 page**，不同 context 之間不會同步。
  - 限制：同一個 context 的 `localStorage` 共用，身分 `ngy:me` 也會共用，沒辦法真的一頁是阿彰、一頁是星星。和身分有關的同步行為（例如各自的行李勾選、各自的錢包）請在報告裡註明是用什麼方式模擬的，或列入實機測試。
  - `t5.py` 示範的是「雲端已有資料、本機有舊資料」時合併的四種情境，可以參考它怎麼預先塞資料。
- 離線 → 編輯 → 恢復連線後的狀態與提示文字（「目前離線，先記在這支手機上」）
- 同步失敗、Firebase 程式庫載入失敗（攔截回傳 500 或逾時）時，App 是否仍可使用、有沒有卡在「連線中…」
- Service Worker：新版上線後舊快取是否清掉、第一次離線開啟能不能顯示（用正式網站觀察即可，不要寫資料）

### 3.4 壓力測試（只在本機假資料庫）

| 項目 | 建議規模 | 觀察 |
|---|---|---|
| 記帳筆數 | 50 / 300 / 1,000 筆 | 首頁與記帳頁渲染時間、捲動是否卡頓、合計是否正確 |
| 清單項目 | 待辦、行李、要買的各 200 筆 | 排序拖曳、勾選回應時間 |
| 心情 | 8 天 × 2 人 × 多次編輯 | 回顧頁渲染、存圖時間 |
| 快速連點 | 同一按鈕 1 秒內點 10 次（新增、刪除、復原、勾選、浮動按鈕） | 有沒有重複寫入、畫面錯亂 |
| 頻繁切換 | 分頁／日期快速來回 100 次 | 記憶體、事件監聽是否累積（`performance.memory`、listener 數量） |
| 長時間執行 | `fast_forward` 模擬開著 12 小時（30 秒重畫的計時器） | 記憶體成長、計時器累積 |
| 低階裝置 | Chrome CPU throttling 4×～6×、Slow 3G | 首次載入、互動延遲 |

請記錄具體數字（毫秒、MB、筆數），不要只寫「順暢」。

### 3.5 裝置、版面與無障礙

- 寬度 320 / 375 / 390 / 430 px，橫向；iOS 安全區域（瀏海、Home Indicator），浮動按鈕與底部分頁是否被擋
- 系統字體放大（`text-size-adjust`、瀏覽器縮放 200%）
- `prefers-reduced-motion`：動畫是否停止
- 對比度（WCAG AA）：特別是焦糖棕小字、珊瑚色警示、插圖上的文字
- 觸控目標 ≥ 44×44 px
- 螢幕閱讀器標籤：浮動按鈕、圖示按鈕、勾選框、全螢幕顯示
- 鍵盤操作（外接鍵盤）能不能完成主要流程

### 3.6 流程與使用體驗評估

請站在**第一次用的星星**和**在日本街頭、單手、網路不穩的阿彰**兩種角度走過下列流程，記錄卡住、要想一下、或多一步的地方：

1. 收到連結 → 加到主畫面 → 選身分 → 加入旅程 → 完成設定檢查清單
2. 早上出門：看今天行程 → 看天氣 → 點第一站的路線
3. 在店裡結帳：記一筆現金支出（含免稅）→ 確認現金錢包
4. 臨時改計畫：找到下一站、看交通時間
5. 迷路或出狀況：打開求助 → 給司機看飯店地址
6. 晚上回飯店：點「回家」→ 寫今天的心情 → 勾行李
7. 最後一天：退稅清單 → 機場行程提醒
8. 回國後：看旅程回顧、存圖分享

評估面向：資訊層級、文案清楚度、操作步數、錯誤預防與復原、一致性（依第 1 節設計規範）、在戶外強光下的可讀性。

